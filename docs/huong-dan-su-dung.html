Dùng model AI ngập lụt trong project thế nào?

Hai năng lực: bản đồ nguy cơ nền (tĩnh) dùng ngay chỉ bằng cách chạy service, và lớp rủi ro động (realtime) cần thêm một tiến trình bơm dữ liệu live định kỳ. Tài liệu này chỉ bạn cả hai — kèm lệnh copy-paste.

🔑 Nguyên tắc quan trọng nhất: “train” ≠ “dùng”

Bạn không train lại mỗi lần dùng. Việc train chạy một lần → đẻ ra các file model đã commit sẵn (.pkl, .parquet, .geojson). Dùng = chạy service đọc các file đó + gọi API. Model mới cũng chạy song song, không đè model cũ — nó có endpoint riêng.

Công cụ cần

Chỉ cần Python + pip (hoặc Docker) để chạy/serve — không cần uv hay conda. uv chỉ là shortcut tuỳ chọn nếu máy có sẵn. Conda chỉ cần khi train lại (vì có thư viện bản đồ nặng); còn để DÙNG thì các file model đã đóng gói sẵn, pip install -r requirements.txt là đủ.

Phần A

Dùng bản đồ NỀN (susceptibility tĩnh)

Đây là cách dùng đơn giản nhất — không đụng gì tới việc train.

1

Chạy AI service

Cách CHUẨN — chỉ cần Python + pip (không cần GDAL/conda). Chạy từ thư mục ai-service:

# từ thư mục ai-service/
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1     # Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
uvicorn serve_susceptibility:app --host 0.0.0.0 --port 5005

Mở http://localhost:5005/docs để thử. Hai cách khác: Docker (docker compose up ai-service) — hoặc nếu máy có sẵn uv thì uv run --with-requirements requirements.txt uvicorn serve_susceptibility:app --port 5005.

2

Gọi endpoint → app render layer

curl "http://localhost:5005/api/susceptibility/grid"              # heatmap nền (GeoJSON 11.534 ô)
curl "http://localhost:5005/api/susceptibility/point?lat=16.055&lon=108.216"  # 1 điểm

App/mobile đọc GeoJSON này làm một lớp bản đồ. Xong — không cần train lại lần nào.

Phần B

Dùng lớp REALTIME (rủi ro động)

Realtime = susceptibility × hệ_số(mưa, nước live). Điểm khác biệt: nó cần dữ liệu live tươi, nên phải có một tiến trình bơm dữ liệu định kỳ.

1

Cập nhật dữ liệu live

Script crawl muangap.danang.gov.vn và ghi latest_snapshot.json (đã sửa để ghi CẢ vào ai-service/data/ → service dùng ngay, không dính seed cũ). Chỉ cần requests (đã có trong requirements.txt):

# dùng chính venv đã tạo ở Phần A (đã có requests)
python scripts/fetch_live_muangap.py                        # chạy 1 lần
python scripts/fetch_live_muangap.py --loop --interval 900  # tự động 15'/lần
Ghi chú

Không vào được muangap (mất mạng / firewall) → script tự fallback dùng file trạm tham chiếu. Snapshot vẫn hợp lệ, chỉ là giá trị ~0 (coi như ngày khô).

2

Gọi endpoint rủi ro động

curl "http://localhost:5005/api/risk/live/grid?min_risk=0.5"       # heatmap ĐỘNG
curl "http://localhost:5005/api/risk/live?lat=16.055&lon=108.216"  # 1 điểm + công thức
curl "http://localhost:5005/api/risk/live/status"                  # snapshot tươi hay 'stale'?
3

Demo không cần chờ trời mưa

Thêm tham số sim_rain_mm để giả lập mưa lớn — “cần gạt” đáng tin nhất khi trình diễn:

curl "http://localhost:5005/api/risk/live?lat=16.055&lon=108.216&sim_rain_mm=120"
# khô → level 'high' (~0.59) ;  mưa 120mm → 'critical' (1.00)
An toàn khi sự cố

Thiếu snapshot → endpoint tự fallback về susceptibility tĩnh (hệ số 1.0), không crash. Snapshot quá cũ → gắn cờ stale trong response để giao diện hiển thị cảnh báo.

Gặp lỗi thì sao?

  • HTTP 503 “AI service unavailable / thiếu file”: chưa chạy service, hoặc thiếu artifact. Kiểm tra flood_susceptibility_model.pkl + feature_grid.parquet + susceptibility_grid.geojson có trong ai-service/ không (nếu chưa, xem docs/CHANGES_AND_RUN.md mục 4 để build lại).
  • Realtime luôn ra như nhau dù đã fetch: đã fix — script giờ ghi vào ai-service/data/latest_snapshot.json (nơi service ưu tiên đọc). Nếu vẫn cũ, xoá file seed cũ đó hoặc đặt biến môi trường AEGIS_SNAPSHOT_PATH trỏ tới file mới.
  • Demo mà rủi ro không tăng: dùng ?sim_rain_mm=120 — không phụ thuộc thời tiết thật.
  • Cờ stale=true: snapshot cũ hơn 6 giờ. Chạy lại fetch. (Vẫn dùng được, chỉ là cảnh báo.)
